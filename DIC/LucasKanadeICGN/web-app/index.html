Initialization · independent of local motion model

For large rigid shifts between sparse pairs. Estimates a global translation before each local solve; CPU FFT and a target-window readback add latency. Ambiguous matches are refused.

For loaded image or video files with large motion. Fits one affine transform from sampled pixels inside the reference mask, then evaluates its displacement at each subset centre. The local solver remains the selected model: Translation estimates only u and v; Affine estimates local deformation too. More scales extend the coarse capture range but need enough image and mask samples, and can increase CPU fit time. This fit runs for each pair, so it is not intended for camera-rate streaming.

For sparse image pairs: six levels, 20 coarse iterations and no temporal prediction, queued for the next calculation. This experimental setting can extend the capture range but does not guarantee convergence or perform global Fourier correlation.

Automatic propagation is active on the default Affine/B-spline preset: two passes per level with CPU reference preparation. It remains available without custom settings. Custom linear/cubic interpolation and experimental GPU reference preparation are incompatible, so Automatic disables propagation there. Each pass tests neighbour translations on rejected subsets and reruns the selected local model from tx/ty with its higher-order terms reset to zero. The selected spatial filter still runs afterwards. Global affine initialization is independent. More passes add work and do not guarantee recovery or 60 FPS.

Solver settings · applied on Start

With three levels the middle uses 4 iterations; with four to six levels, intermediate levels use 8. For sparse image pairs with large shifts, try six levels, 20 coarse iterations and disable temporal warm start. More levels are experimental and do not guarantee convergence. One level uses the fine limit. Temporal fine correction is used only with two levels. More overlap increases the grid density and cost.

Rejected-only repairs failed subsets with recentered medians from valid neighbours as seeds for the next finer solve. All subsets also median-smooths accepted motion parameters after every scale, from coarsest to finest; rejected subsets are still repaired as seeds. Statuses are not promoted by filtering. Whole-field smoothing is explicit and can blur localized deformation. This is separate from Median smoothing in Results.

    FIRST EXPERIMENT

    Choose the right workspace

    Use Live for continuous camera or stream processing with a lightweight preview. Use Analysis for file sequences, saved-field review, post-processing, measurements and exports. Switching workspaces preserves the session; it does not change the solver.

    1. Input: open an image folder, a video or a camera. A demonstration is a good first check.
    2. Mask: keep the specimen and add holes. Apply commits the pending ROI locally; it does not build the GPU reference.
    3. Solve: use the preset first. Start calculation prepares the reference, mask and settings together, then solves. Saved fields are available in Results. Fixed and consecutive references measure different things.
    4. Results: choose a quantity, play the saved sequence or drag its slider. Create and name multiple points, lines, zones and extensometers; extract their evolution and export the CSV.

    Space: play/pause saved results in Results. R: capture reference. Esc: clear measurement selection. Shortcuts are inactive while editing a form or mask.

    No upload or account. Camera permission is local. This companion is not qualified for hand-held metrology; Python is the primary scientific supervisor.
    Browser engine: canonical WGSL shared with native Python. Source & documentation. Your camera stays on this device.
